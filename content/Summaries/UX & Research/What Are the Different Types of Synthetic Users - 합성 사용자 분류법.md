# What Are the Different Types of Synthetic Users - 합성 사용자 분류법

## 사용자 메모

- AI 합성 사용자는 단일 개념이 아니라 실제 데이터 기반 정도에 따라 나뉘는 5가지 유형의 총칭이다.
- 가장 약한 유형은 단순 역할 부여 프롬프트를 쓰는 “AI 프로토 페르소나”이고, 가장 강한 유형은 개인 데이터를 모델링한 “디지털 트윈”이다.
- 인터뷰·설문·데이터 로그 등 실제 리서치 산출물을 참조할수록 신뢰도가 높아지며, 리서치 기반(Research Grounded) 유형이 현실적 활용점으로 권장된다.
- 이 분류 체계는 연구 목적에 맞는 AI 리서치 도구를 고를 때 판단 기준으로 쓸 수 있다.

## 한 줄 요약

“합성 사용자”는 단일한 방법론이 아니라, 실제 사용자 데이터에 얼마나 근거하는지에 따라 **AI 프로토 페르소나 → 인구통계 기반 → 페르소나 기반 → 리서치 기반 → 디지털 트윈**으로 나눌 수 있는 포괄 범주다.

## 핵심 구조

### 1. 문제의식

- UX 리서치 참여자 모집은 비싸고, 패널 품질·주의 집중·설문 농장 같은 문제가 있다.
- AI가 사람의 태도·신념·행동을 대신 시뮬레이션할 수 있다면 빠르고 저렴한 인사이트 생성이 가능해 보인다.
- 하지만 “합성 사용자”라는 말이 디지털 트윈, 합성 페르소나, 생성 에이전트 등과 뒤섞여 쓰이기 때문에 용어 정리가 필요하다.

### 2. 분류 비유: 새의 분류법

- 새를 단일 특징 하나로 정의하기 어렵듯, 합성 사용자도 한 가지 특징만으로 구분하기 어렵다.
- 중요한 것은 여러 특징의 조합과 위계다.
- 저자들은 합성 사용자를 하나의 “종”이 아니라 여러 종을 포함하는 “속(genus)”에 가깝게 본다.

### 3. 다섯 가지 합성 사용자 유형

- **AI 프로토 페르소나**
  - 단순 역할극 프롬프트로 만든 가장 약한 유형.
  - 예: “당신은 세계 최고 수준의 파이썬 프로그래머입니다.”
  - 실제 리서치가 아니라 넓은 가정에 기반한다.

- **인구통계 기반**
  - 나이, 성별, 직업, 지역 등으로 집단 경향을 근사한다.
  - 프로토 페르소나보다는 낫지만, UX 문제처럼 인구통계와 행동/태도 사이의 관계가 약한 경우 한계가 크다.

- **페르소나 기반**
  - 더 풍부한 페르소나 문단을 제공하고 그 관점에서 답하게 한다.
  - 여전히 실제 데이터 근거가 약하므로 대략적인 집단 경향을 보는 수준에 머문다.

- **리서치 기반**
  - 실제 인터뷰, 설문, 제품 분석 데이터, 고객지원 로그 등 추적 가능한 리서치 산출물을 프롬프트에 포함한다.
  - 개별 인간을 그대로 모델링하지는 않지만, 공개 LLM 지식만으로는 얻을 수 없는 조직 내부 사용자 데이터에 근거한다.

- **디지털 트윈**
  - 개인별 풍부한 데이터를 사용해 데이터셋 안의 각 개인을 모델링하려는 접근.
  - 근거 수준은 가장 높지만, 실제 배포 환경에서 얼마나 정확한지는 아직 열린 연구 질문이다.

## 관찰 / 인사이트

### 데이터 근거 수준이 핵심 판단 기준이다

합성 사용자 논의에서 “AI가 사람처럼 답했다”보다 더 중요한 질문은 다음이다.

- 어떤 데이터를 넣었는가?
- 그 데이터는 실제 사용자에게서 온 것인가?
- 집단 수준 경향을 모사하는가, 개인 응답을 모사하는가?
- 결과를 실제 인간 데이터와 비교 검증했는가?

즉, 합성 사용자의 품질은 모델의 유창함보다 **grounding**과 **검증 가능성**에 더 크게 좌우된다.

### 대부분의 실무 사례는 하이브리드일 가능성이 높다

현실의 프롬프트는 깔끔하게 한 유형에만 속하지 않는다. 예를 들어 실제 응답자의 나이·성별·이념·소득 같은 변수를 넣어 설문 응답을 생성하면, 이는 인구통계 기반이면서 페르소나 기반이고, 아주 약한 디지털 트윈 요소도 포함한다.

따라서 실무에서는 “이건 디지털 트윈인가 아닌가”보다 “어떤 속성은 실제 데이터에 기반하고, 어떤 속성은 가정인가”를 분리해 적는 편이 유용하다.

### 생성 에이전트와 합성 응답자는 구분해야 한다

저자들은 생성 에이전트를 이 분류에 넣지 않는다. 이유는 생성 에이전트가 단발 응답을 시뮬레이션하는 것이 아니라, 시간이 지나며 행위를 수행하는 actor에 더 가깝기 때문이다.

UX 리서치 관점에서는 다음처럼 구분할 수 있다.

- 합성 응답자: 설문, 인터뷰 질문, 컨셉 평가에 대한 응답을 생성
- 생성 에이전트: 일정 기간 동안 행동, 상호작용, 의사결정 과정을 시뮬레이션

## 실무 활용 예시

### 예시 1. 컨셉 초기 탐색

- 사용 유형: AI 프로토 페르소나 또는 페르소나 기반
- 가능한 질문:
  - “이 제품 설명에서 어떤 점이 헷갈릴까?”
  - “초보 사용자 페르소나가 온보딩에서 막힐 지점은?”
- 주의:
  - 실제 사용자 인사이트가 아니라 가설 생성 도구로만 사용한다.
  - 의사결정 근거로 쓰기 전에 인간 리서치로 확인한다.

### 예시 2. 세그먼트별 메시지 초안 테스트

- 사용 유형: 인구통계 기반 + 페르소나 기반
- 가능한 입력:
  - 연령대, 직업, 사용 맥락, 구매 동기, 불안 요소
- 가능한 산출:
  - 각 세그먼트가 이해하기 어려워할 표현
  - 메시지별 예상 반응
  - 인터뷰 가이드나 설문 문항 개선안
- 주의:
  - 인구통계가 실제 태도·행동 차이를 잘 설명하는지 별도 검토가 필요하다.

### 예시 3. 리서치 저장소 기반 합성 사용자

- 사용 유형: 리서치 기반
- 가능한 입력:
  - 인터뷰 요약
  - 설문 결과
  - CS 로그
  - 제품 사용 분석 데이터
- 가능한 활용:
  - 기존 리서치에서 반복적으로 나타난 pain point 질의
  - 새로운 기능 아이디어에 대해 과거 사용자 증거 기반으로 반응 가설 생성
- 주의:
  - 출처 추적, 데이터 최신성, 개인정보 제거, human review가 필요하다.

### 예시 4. 개인 수준 예측 또는 응답 재현

- 사용 유형: 디지털 트윈
- 가능한 입력:
  - 개인별 과거 응답
  - 행동 로그
  - 구매/사용 이력
  - 선호와 맥락 데이터
- 가능한 활용:
  - 개인화 실험
  - 반복 설문 비용 절감 가설 검증
- 주의:
  - 정확성, 동의, 개인정보, 윤리 문제가 가장 크다.
  - “그럴듯한 개인 응답”과 “실제 개인을 정확히 모델링한 응답”을 구분해야 한다.

## 체크리스트: 합성 사용자 프로젝트를 평가할 때

- [ ] 합성 사용자의 유형을 명시했는가?
- [ ] 사용한 데이터의 출처를 적었는가?
- [ ] 실제 사용자 데이터와의 grounding 수준을 설명했는가?
- [ ] 집단 수준 시뮬레이션인지 개인 수준 모델링인지 구분했는가?
- [ ] 프롬프트에 들어간 정보와 들어가지 않은 정보를 분리했는가?
- [ ] 결과를 인간 응답 또는 기존 리서치와 비교 검증했는가?
- [ ] 생성 결과를 “인사이트”가 아니라 “가설”로 다룰 구간을 정했는가?
- [ ] 개인정보, 동의, 데이터 보존 정책을 검토했는가?

## 한계 / 주의점

- 이 글의 분류법은 저자들이 명시하듯 예비 taxonomy다. 기술과 용어가 빠르게 변하면 분류도 바뀔 수 있다.
- 합성 사용자는 모집 비용 문제를 줄일 수 있지만, 실제 사용자를 완전히 대체한다는 의미는 아니다.
- 특히 UX 리서치에서 인구통계 정보만으로 행동이나 사용성 문제를 예측하는 것은 위험하다.
- 디지털 트윈은 가장 강한 근거를 갖는 것처럼 보이지만, 실전 정확성은 아직 검증이 충분하지 않다.
- 벤더가 “synthetic user”라고 부르는 것이 어떤 유형인지 반드시 확인해야 한다.

## 바로 써먹을 질문 프롬프트

```text
우리가 만들려는 synthetic user를 다음 기준으로 분류해줘.
1. AI proto persona / demographic based / persona based / research grounded / digital twin 중 어디에 가까운가?
2. 어떤 데이터가 실제 사용자 데이터이고, 어떤 데이터가 가정인가?
3. 집단 수준 경향을 보는 용도인가, 개인 수준 응답을 예측하는 용도인가?
4. 이 결과를 의사결정에 쓰기 전에 어떤 human research로 검증해야 하는가?
5. 개인정보·동의·윤리 측면에서 확인해야 할 리스크는 무엇인가?
```

## 내 작업에 적용할 때의 기준

- 아이디어 발산이나 리서치 질문 만들기: 프로토/페르소나 기반도 허용
- 메시지·컨셉 초안 점검: 페르소나 기반 + 실제 리서치 조각을 섞되, 결과는 가설로만 취급
- 리서치 repository 질의: 반드시 출처가 있는 리서치 기반 접근 사용
- 사용자 행동 또는 개인 응답 예측: 디지털 트윈이라고 주장하려면 개인 수준 데이터와 검증 설계가 필요
