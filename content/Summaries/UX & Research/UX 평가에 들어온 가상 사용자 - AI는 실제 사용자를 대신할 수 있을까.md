# UX 평가에 들어온 가상 사용자 - AI는 실제 사용자를 대신할 수 있을까

## 한 줄 요약

AI 가상 사용자는 실제 사용자를 대체하는 존재가 아니라, 초기 UX 평가에서 빠르게 가설을 만들고 실제 리서치 설계를 더 선명하게 만드는 보조 도구로 써야 한다.

## 사용자가 남긴 핵심 메모

- 사용자 테스트는 모집과 일정 조율 때문에 최소 2주 이상 걸리기 쉽다.
- AI 시뮬레이션의 가치는 정답이 아니라 빠른 가설 생성과 실제 리서치 설계 보조에 있다.
- 가상 사용자 응답은 그럴듯하므로 더 위험할 수 있다. 그럴듯함은 예측 가능성과 다르다.
- 쓸모의 기준은 “대체할 수 있는가”가 아니라 “어디에 쓰는가”다.

## 핵심 내용 구조

### 1. 배경: 사용자 테스트는 느리고 제품 의사결정은 빠르다

- 실제 사용자 테스트는 인터뷰이 모집, 일정 조율, 진행, 분석까지 시간이 걸린다.
- 초기 아이디어나 프로토타입 단계에서는 리서치가 제품 개발 속도를 따라가기 어렵다.
- 그래서 실제 사용자 전에 LLM 기반 가상 사용자에게 먼저 물어보는 흐름이 생겼다.

### 2. Generative Agents: 기억·반성·계획을 가진 에이전트

- Generative Agents 연구는 LLM이 기억, 반성, 계획을 결합하면 사회적 행동처럼 보이는 상호작용을 시뮬레이션할 수 있음을 보여준다.
- 다만 이것은 “AI가 진짜 사람이 되었다”는 뜻이 아니라, 특정 역할을 수행하는 role-play로 이해해야 한다.
- 이 흐름은 특정 사용자 집단의 반응도 시뮬레이션할 수 있는지라는 질문으로 이어진다.

### 3. Silicon Sampling과 Synthetic Users

- Silicon Sampling은 LLM을 설문 응답자처럼 사용해 집단의 태도나 선호를 추정하려는 접근이다.
- Synthetic Users는 특정 서비스나 인터페이스를 보고 반응하는 사용자 역할을 LLM이 수행하게 하는 접근이다.
- UX에서는 “초보 사용자가 이 온보딩을 헷갈려 할까?”, “20대 대학생은 이 가격 정책을 어떻게 받아들일까?” 같은 질문을 빠르게 탐색하는 데 쓰일 수 있다.

### 4. 가상 사용자의 쓸모: 답보다 가설

- 가상 사용자는 실제 사용자의 행동을 정확히 예측하는 도구가 아니다.
- 대신 초기 단계에서 놓친 사용 맥락, 잠재적 불편, 질문해야 할 가설을 빠르게 뽑아내는 데 유용하다.
- 실제 사용자 조사를 하기 전, 인터뷰 질문·사용성 테스트 태스크·관찰 포인트를 정교하게 만드는 사전 점검 도구로 보는 편이 안전하다.

### 5. 한계: 그럴듯함과 예측 가능성은 다르다

- LLM 응답은 자연스럽고 설득력 있게 보일 수 있지만, 실제 사용자의 행동·감정·맥락을 대표한다고 볼 수는 없다.
- 페르소나 프롬프트는 실제 사회경제적 조건, 동기, 제약, 경험의 다양성을 충분히 반영하지 못한다.
- 모델의 학습 데이터와 프롬프트 방식에 따라 응답이 크게 달라질 수 있다.
- 따라서 가상 사용자 결과를 제품 의사결정의 최종 근거로 쓰면 위험하다.

## 관찰과 인사이트

### “리서치 대체” 프레임보다 “리서치 준비” 프레임이 안전하다

가상 사용자를 실제 사용자 대신 쓰겠다고 보면 검증 불가능한 예측에 기대게 된다. 반대로 실제 리서치 전에 질문을 날카롭게 만들고, 프로토타입의 취약 지점을 미리 찾고, 리크루팅 조건을 정리하는 도구로 쓰면 리서치 품질을 높일 수 있다.

### AI 응답의 위험은 부정확함보다 설득력이다

부정확한 답은 쉽게 의심할 수 있지만, 그럴듯한 답은 실제 근거처럼 소비되기 쉽다. 따라서 결과물에는 항상 “가설”, “가능성”, “검증 필요” 같은 라벨을 붙이고, 실제 사용자 데이터와 구분해야 한다.

### 가상 사용자는 평균 사용자를 만들기 쉽다

LLM은 특정 페르소나를 부여해도 흔하고 일반적인 답을 내놓는 경향이 있다. 극단적 상황, 소수자 경험, 실제 제약 조건, 맥락의 우연성은 약하게 표현될 수 있다. UX 평가에서 바로 그런 예외와 맥락이 중요하다는 점을 잊으면 안 된다.

## 실무 활용 예시

### 초기 프로토타입 점검

```text
당신은 처음으로 이 서비스를 사용하는 30대 직장인입니다.
아래 온보딩 화면을 보고 어떤 정보가 헷갈리는지, 가입을 망설이게 만드는 문구가 있는지 말해주세요.
답변은 확정 판단이 아니라 실제 사용자 테스트에서 확인할 가설 목록으로 작성해주세요.
```

### 리서치 설계 보조

```text
아래 제품 아이디어에 대해 실제 사용자 인터뷰에서 확인해야 할 가설 10개를 작성해주세요.
각 가설마다 관찰 질문, 인터뷰 질문, 확인해야 할 행동 증거를 함께 제안해주세요.
```

### 사용성 테스트 태스크 만들기

```text
아래 프로토타입을 테스트하기 위한 사용성 테스트 태스크를 작성해주세요.
가상 사용자의 예상 반응을 먼저 적되, 실제 테스트에서 검증해야 하는 관찰 포인트와 실패 신호를 분리해주세요.
```

## 체크리스트

- [ ] 이 결과를 “사용자 반응의 예측”이 아니라 “검증할 가설”로 표시했는가?
- [ ] 실제 사용자 테스트에서 확인할 질문과 관찰 포인트로 변환했는가?
- [ ] 페르소나가 너무 일반적이지 않은가? 실제 맥락, 제약, 동기, 경험 수준이 들어갔는가?
- [ ] 하나의 모델·하나의 프롬프트 결과만으로 판단하지 않았는가?
- [ ] 실제 사용자 데이터와 가상 사용자 응답을 문서에서 명확히 구분했는가?
- [ ] 의사결정 전에 실제 사용자나 행동 데이터로 검증할 계획이 있는가?

## 주의점과 한계

- 가상 사용자는 실제 사용자를 대표하지 않는다.
- 페르소나가 정교해도 실제 환경의 압박, 시간 제약, 사회적 맥락, 감정적 반응을 완전히 재현하기 어렵다.
- LLM은 모르는 것도 그럴듯하게 말할 수 있으므로, “왜 그렇게 생각하는지”보다 “무엇을 실제로 검증해야 하는지”에 초점을 맞춰야 한다.
- 접근성, 취약계층, 문화적 맥락처럼 실제 경험 차이가 중요한 문제는 반드시 사람을 만나야 한다.
- 정량 예측, 시장 규모 추정, 전환율 예측처럼 실제 데이터가 필요한 질문에는 부적합하다.
