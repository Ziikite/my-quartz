# AI 디자인 레퍼런스 리서치 자동화 - Codex와 Human-in-the-loop 갤러리

## 사용자 메모

- 레퍼런스 수집 후 웹페이지 형태로 내용들을 필터링해서 볼 수 있게 만든 사례.
- AI에게 디자인 레퍼런스 리서치를 맡긴 Codex 활용 사례.
- 수집된 자료의 썸네일과 핵심 내용을 먼저 표기하여 빠르게 내용 파악.
- 방대한 자료를 카테고리로 구분해 취사 선택해서 확인 가능.
- 이미지 및 내용 기반 카테고리 구분 과정에서 일부 오류 발생.
- 배울점: 작업에 따라 AI에게 다 맡기지 않고 사람이 개입할 자리를 만들어 두는 것이 더 나은 선택일 수 있다.

## 한 줄 요약

Codex로 자동차 정비 서비스의 디자인 레퍼런스 이미지를 대량 수집하고 HTML 갤러리로 필터링 가능하게 만든 사례로, **검색 범위는 사람이 좁히고 수집·시각화는 AI가 하며, 오류가 많은 이미지 분류는 사람이 빠르게 수정할 수 있는 UI를 추가한 Human-in-the-loop 워크플로**가 핵심이다.

## 핵심 구조

### 1. 문제: 디자인 레퍼런스 수집은 중요하지만 시간이 오래 걸린다

- 새로운 도메인의 프로젝트를 시작할 때 업계의 시각 언어를 살피는 일이 필요하다.
- 보통 사람이 직접 50개 내외 이미지를 모아 피그마에 붙여두고 논의한다.
- 이 과정은 3~5일 정도 걸릴 수 있다.

### 2. 결과: AI가 1000여 개 이미지를 수집했다

- AI는 1000여 개 이미지를 모았고, 실무 적용 가능 자료는 200~300개 정도였다.
- 사람이 직접 모으는 50개 내외보다 4~5배 많은 양이다.
- 전체 작업은 만 하루 정도 걸렸고, 사람이 프롬프트 입력/결과 확인에 쓴 시간은 2~3시간 정도였다.
- 다음 프로젝트에서는 유사한 방식으로 1시간 이내 리서치도 가능할 것으로 봤다.

### 3. 산출물: HTML 갤러리

- 이미지를 한 화면에서 카테고리별로 검토할 수 있는 HTML 갤러리로 정리했다.
- 썸네일과 핵심 내용을 먼저 보여줘 빠른 파악이 가능하다.
- 키워드/카테고리별 필터링으로 방대한 자료를 취사 선택할 수 있다.
- 이미지를 직접 저장하지 않고 원본 이미지 URL과 출처 URL을 연결해 로컬 리소스를 줄였다.
- 원본 페이지로 이동해 이미지가 실제로 어떤 맥락에서 쓰였는지도 확인할 수 있다.

### 4. 작업 방식: LLM Wiki + Codex

- 프로젝트 메일, 요구사항, 제안 내용 등을 wiki에 저장해 Codex가 참조하게 했다.
- 매번 채팅창에 같은 정보를 설명하지 않아도 AI가 wiki를 읽고 일관된 기준으로 작업했다.
- 프롬프트는 대략 다음 흐름이었다.
  - 프로젝트 요구사항에서 참고할 만한 사이트 수집
  - 수집한 사이트 목록 안에서 “자동차 정비”의 긍정적 브랜드 이미지 검색
  - 수집 이미지를 하나의 HTML 파일로 시각화

### 5. 핵심 노하우: 프롬프트보다 검색 범위를 좁히는 것이 중요했다

- “자동차 정비 관련 이미지를 찾아라”처럼 넓게 시키면 범위가 너무 커진다.
- 먼저 참고할 사이트 목록을 만들고, 그 안에서 이미지를 찾게 하니 상업적으로 정돈된 이미지가 더 잘 모였다.
- 즉 프롬프트를 미세하게 다듬는 것보다 **어디를 볼지 먼저 제한하는 것**이 결과를 빠르게 안정시켰다.

### 6. 한계: 자동 분류는 시각적 속성을 충분히 보지 못했다

- AI가 실사 사진을 기대한 카테고리에 공구 아이콘/일러스트를 섞어 넣었다.
- 수집할 때는 이미지를 봤지만, 분류할 때는 수집 단계에서 저장된 설명 텍스트를 기준으로 판단했기 때문이다.
- 따라서 이미지의 실제 시각적 속성을 기준으로 한 분류가 잘 되지 않았다.

### 7. 해결: 자동화 고도화 대신 수동 편집 UI를 추가했다

- 자동 분류를 더 잘하게 만들기 위해 프롬프트를 계속 다듬는 대신, 갤러리에 select 기반 수동 편집 UI를 추가했다.
- 잘못 분류된 이미지만 사람이 바꾸면 바로 재분류되게 했다.
- 수정은 30분도 걸리지 않았다.
- 이 작업에서는 “AI에게 모두 맡기기”보다 “사람이 빠르게 개입할 수 있는 자리 만들기”가 더 효율적이었다.

## 관찰 / 인사이트

### Human-in-the-loop는 자동화 실패의 보완책이 아니라 설계 전략이다

이 사례에서 사람은 AI가 실패한 뒤 어쩔 수 없이 개입한 것이 아니다. 사람이 개입할 수 있는 UI를 만들었기 때문에 자동화의 품질 문제를 빠르게 흡수할 수 있었다. 완전 자동화를 목표로 삼기보다, **오류가 예상되는 지점에 가벼운 수동 수정 장치를 붙이는 것**이 더 실용적이다.

### AI에게 “무엇을 찾을지”보다 “어디서 찾을지”를 주는 편이 강하다

디자인 레퍼런스는 검색 범위가 넓으면 품질이 급격히 떨어진다. 이 사례는 AI의 검색 품질을 높이기 위해 프롬프트를 길게 쓰기보다, 먼저 참고 사이트라는 탐색 공간을 좁히는 접근을 택했다. 이는 리서치 자동화에서도 샘플링 프레임을 설계하는 것과 비슷하다.

### 산출물 형태가 작업 재사용성을 만든다

피그마 보드에 이미지를 늘어놓는 방식은 한 번의 프로젝트 논의에는 유용하지만, 필터링·검색·재사용에는 약할 수 있다. HTML 갤러리는 다음 프로젝트에서도 꺼내 쓸 수 있는 자산이 된다. AI 자동화의 가치는 “많이 모으기”보다 **다시 찾고 고를 수 있는 형태로 남기기**에서 커진다.

### 이미지 기반 AI 워크플로는 중간 메타데이터 설계가 중요하다

분류 오류의 원인은 AI가 이미지를 다시 보지 않고 텍스트 설명만 보고 분류한 데 있었다. 따라서 이미지 리서치 파이프라인에서는 다음을 설계해야 한다.

- 이미지 자체를 다시 평가하는 단계가 있는가?
- alt/캡션/주변 텍스트가 실제 이미지 내용과 어긋날 가능성을 다루는가?
- 실사/아이콘/일러스트/3D 렌더 같은 시각 형식 메타데이터를 따로 저장하는가?
- 사람이 수정한 카테고리가 다음 자동 분류에 학습/참조될 수 있는가?

## 실무 활용 예시

### 예시 1. 디자인 레퍼런스 수집 워크플로

1. 프로젝트 요구사항과 브랜드 키워드를 wiki/문서에 정리한다.
2. AI에게 관련성이 높은 참고 사이트 목록을 먼저 만들게 한다.
3. 그 사이트 목록 안에서만 이미지/페이지를 수집하게 한다.
4. 이미지 URL, 출처 URL, 설명, 키워드, 임시 카테고리를 저장한다.
5. HTML 갤러리로 썸네일, 설명, 출처, 필터를 제공한다.
6. 카테고리 오류는 수동 편집 UI로 빠르게 수정한다.
7. 최종 후보만 피그마/디자인 보드로 옮긴다.

### 예시 2. 갤러리 카드에 넣을 필드

- 썸네일 이미지
- 원본 이미지 URL
- 출처 페이지 URL
- 사이트/브랜드명
- 자동 생성 설명
- 카테고리
- 시각 형식: 실사, 아이콘, 일러스트, 3D, UI 캡처 등
- 사람이 검수했는지 여부
- 사용 가능성: 참고 가능, 제외, 재검토

### 예시 3. 사람이 개입할 지점

- 참고 사이트 목록 승인
- 상업적/브랜드 톤에 맞지 않는 자료 제거
- 실사/아이콘/일러스트 같은 시각 형식 재분류
- 저작권/출처 확인
- 최종 moodboard 후보 선택

## 체크리스트

- [ ] AI가 탐색할 사이트/출처 범위를 먼저 좁혔는가?
- [ ] 결과물을 단순 이미지 묶음이 아니라 필터링 가능한 갤러리로 만들었는가?
- [ ] 이미지 URL과 출처 URL을 함께 저장했는가?
- [ ] 자동 분류 오류를 사람이 빠르게 수정할 UI가 있는가?
- [ ] 실사, 아이콘, 일러스트 등 시각 형식 메타데이터를 별도로 관리하는가?
- [ ] 사람이 수정한 결과가 다음 프로젝트의 기준으로 재사용될 수 있는가?
- [ ] 최종 후보를 디자인 보드로 옮기기 전에 출처와 맥락을 확인했는가?

## 한계 / 주의점

- 원문 사례의 이미지 수집 방식과 출처 사용은 프로젝트 맥락에 따라 저작권/이용 조건 검토가 필요하다.
- 이미지 URL만 저장하면 원본 페이지가 바뀌거나 이미지가 사라질 수 있다.
- 자동 설명 텍스트가 실제 이미지 내용과 다를 수 있으므로, 중요한 분류는 이미지 자체를 다시 확인해야 한다.
- AI가 수집한 1000여 개 중 실무 적용 가능 자료가 200~300개였다는 점에서, 대량 수집은 곧바로 고품질을 의미하지 않는다.
- 수동 편집 UI가 없으면 오류 수정 비용이 다시 커질 수 있다.

## 재사용 문장

> AI 자동화의 목표는 사람을 완전히 빼는 것이 아니라, 사람이 판단해야 할 지점을 더 작고 빠르게 만드는 것이다.

> 디자인 레퍼런스 리서치에서 AI의 품질은 프롬프트의 정교함만이 아니라, 어디를 검색하게 할지 정하는 탐색 범위 설계에 크게 좌우된다.
