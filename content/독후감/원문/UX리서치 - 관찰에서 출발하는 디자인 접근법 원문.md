## 참가자 스크리닝 방법

### 1. 인구 통계가 아닌 행동을 심사하라 

- 디지털 기술 (내비게이션, 양식 채우기, 검색과 같은 웹 관용구에 대한 사용자 경험)
- 태스크 지식 (사진, 주식 거래, 계보학 같은 특정 분야에 대한 사용자 지식)

→ 이 2가지 요인에 대해 높음, 낮음으로 분류할 것 

> [!note]

### 2. 정확한 질문을 던져라 

누군가에게 “자주”는 다른 사람에게 “가끔”이다. 

⇒ 온라인에서 무엇을 하고 있는지, 스스로 하는지, 다른이의 도움을 받는지 물어볼 것 

### 3. 부적합한 후보자를 초반에 찾아내라

- 배제질문 : 하나의 답변으로 후보를 배제하는 경우
- 균형질문 : 서로다른 카테고리에서 균등한 수의 사용자를 모으고 싶은 경우

### 5. 참가자 각자의 기대치를 관리할 것

스크리닝 질문에 답하는 것 = 리서치 참가를 위한 전제 조건임을 알릴 것

## 디자인 애스노그래피란? 

- 결과는 팀 혹은 조직으로 한정됨

### 디자인 애스노그래피 접근 방법

- 사용자가 달성하고자 하는 목표는 무엇인가?
- 현재 어떻게 하고 있는가?
- 어떤 부분을 좋아하거나 싫어하는가?
- 도중에 어떤 어려움을 겪는가?
- 어떤 임시 해결방안을 사용하는가?

## 애스노그래픽 인터뷰 구조화

### 맥락의 중요성

발견단계에서 고객 인터뷰 목적 : 사람들이 `왜` 원하는지 알아내는 것

- **동기** : 사용자가 완수하고자 하는 것은 무엇인가?
- **활동** : 현재 이용자는 어떻게 하고 있는가? 
- **문제** : 현재 프로세스의 어려움/만족스러운 순간은 무엇인가?

> [!note]

### 준비

1. 어떤 인터뷰도 안하는 것보다 나음
1. 인터뷰하고자 하는 사람들이 명확한 유형으로 나뉜다면 유형별로 4~6명으로 시작
1. 어떤 유형이 있는지 모르면 8명으로 시작

→ 1차로 20명 가량의 사용자를 포함한 후 나중에 특정 질문을 해결하기 위해 더 작은 표본을 방문 

- 토론 가이드를 간단하게 만들 것
= 이야기를 이끌어내고 구조화하기 위한 발판

## 사용성 전문가 리뷰에서 개인 의견 피하기

## 참가자와 인터랙션할 때 편향

- 모든것을 표준화하라 : 리서치 프로토콜, 진행자 대본, 질문 등을 표준화하라. 
모든 조건에서 모든 참가자에게 동일한 방식으로 동일한 프로토콜을 준수해라. 
대본에 충실해라. 

## 사용성 이슈 우선순위 정하는 법

- 심각 : 일부 사용자의 기본 태스크 완료의 속도를 현저하게 낮추며, 사용자가 대처 방안을 찾게 만들 수 있다. 가급적 빨리 고칠 것
- 낮음 : 품질 이슈

## 인사이트, 가설 및 테스트 가능한 디자인 아이디어 개발하기

- 디자인 솔루션 만들기 : 근본적인 문제를 해결하기 위해 만들 수 있는 가장 간단한 변화는 무엇인가?
- 직접 인용문 : “이 구독하기 버튼의 의미를 모르겠어요. 주기적으로 결제되는건가요?”
- 사용자 목표 : 점심 무렵에 배달 경로를 계획하기 때문에 정오에는 베이커리나 슈퍼마켓 근처에 있길 원한다. 
- 사용자 행동 : 새로운 비용 청구를 시작할 때, 그녀는 이전 청구를 불러와서 템플릿으로 사용한다.
- 고충점 : 배터리 수명 때문에 30분 이상 연속해서 작동이 어렵다.
